# Synthetic Demo Workflow

The public tutorial uses the 15 files in `demo-files/`.

## Why synthetic?

Real tender documents can contain bidder names, public-office details, bank
information, tax identifiers, addresses, signatures and other sensitive or
unnecessary information. The demo set therefore contains only fictional or
masked content.

## Planned flow

1. Upload this repository skeleton to GitHub.
2. Confirm the final repository owner/URL.
3. Replace `<GITHUB_USERNAME>` in the README.
4. Use the raw GitHub URLs listed in `demo_manifest.csv`.
5. Generate the final synthetic Technical Bid Response PDF containing the 15 links.
6. Run that source PDF through the actual v1.0 EXE.
7. Verify all documents, TOC links, bookmarks, CSV output and the intentional blank-document `CHECK`.
8. Record the tutorial only after the end-to-end demo passes.

`02_Blank_Voucher.pdf` is intentionally blank and should be retained exactly as-is.
